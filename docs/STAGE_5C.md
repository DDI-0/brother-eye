# Stage 5C — Arbiter and shared local assistance

Implemented and verified 12 October 2026. The Arbiter of Dawn now makes ideological decisions, travels and assists. The other three agents retain explicitly labelled foundation routines until 5D. No AI service, new authority, city geometry or character asset changes.

## Delivered behavior

`backend/agent_behavior.py` supplies local observation, request selection/claiming, physical assistance, outcomes, bounded learning and audit. The Arbiter observes people within **8 m**, vertical difference **≤2 m**, at most once per **5 simulated seconds**. This is proximity sensing, not line-of-sight surveillance. At most 16 observations survive; evidence older than 600 simulated seconds is ineligible until observed again. The inspector's global name lookup does not enter the planner.

Observed social need **>75** can create one open/claimed request per recipient. The Arbiter chooses observed severity descending, request age ascending, then stable request ID; trust/friendship cannot override that ordering. Candidate snapshots, evidence IDs and the reason are persisted with each significant selection, so evidence remains auditable after the observation cache rotates. A committed action remains held through travel; urgent physiology, explicit redirection, completion/failure or expiry triggers a fresh choice. Without an eligible request, the Arbiter visits their own known park/food/home points to gather local evidence. Urgent hunger ≥90 or energy ≤10 takes priority, with home/food recovery hysteresis. Brother Eye's held destination override still outranks these priorities.

Assistance approaches a point **1.2 m beside the last observed recipient position**, directed toward the approaching actor. The first integration run exposed body-to-body targeting stopping against the recipient; the offset fixes that collision without disabling it. The actor must report actual arrival, then verify the recipient is still at the observed meeting point and within **2 m** on the same level. A busy/travelling, non-arrived, explicitly directed or physiologically urgent recipient declines. Recipient state/goals are not forced.

Both bodies need fresh accepted physical reports. Dwell advances only on the live authoritative clock, with both arrived and close; pause/offline grants no dwell. **Five simulated seconds** grants exactly one **5-point social-need reduction**, one cooperation memory and **+1 directed trust**. No remote hunger/energy benefit. An explicit decline gives −1 trust; departure, route failure, expiry and interruption give no trust penalty or social reward. Outcomes apply a bounded **60-second per-pair cooldown**. Route wait cancels the autonomous request; explicit Brother Eye route waits retain the existing held-override semantics. Exceptional Agents have at most 8 directed relationships; new experience evicts a non-companion contact by stable ID when full, so learning stays bounded without dropping the new result. Companion membership remains fixed.

## Persistence and UI

Schema **6**, protocol **1**. Schema-5 migration adds behavior fields and empty bounded request/history containers, activates only the Arbiter, preserves all 34 people/ordinary fields/held overrides, and advances revision once. Older migration chains still advance revision once for the complete upgrade. Existing receipts remain byte-identical; their old revisions cannot replace the migrated snapshot. Normal launch migrates the real save; every experiment here used disposable databases.

World `assistance_requests` and `agent_history` retain at most 64 records each. Active claims cannot be evicted; terminal requests retire first. Each action has a fresh goal ID, target, evidence, selected time and partial dwell. Significant requests, selections, terminal outcomes, rewards, trust and memories commit atomically to SQLite `events` as `agent_events`; movement-command consequences share the existing receipt transaction. Failed commits restore the complete live before-state. Ordinary clock/observation/partial-dwell updates retain the existing two-second checkpoint policy; an abrupt uncheckpointed crash may lose recent partial time, but cannot duplicate a committed reward. Completed request IDs and terminal state deduplicate rewards. Full autonomous audit is stored in SQL; the UI displays recent outcomes, not SQL pagination for these events.

Inspection Overview now includes active/foundation status, immutable core, physical action/dwell, candidate evidence, local observations, recent outcomes and directed trust. Existing known-destination controls exclude the dynamic `assistance` goal. Follow HUD handles it without indexing an unknown place. Open `Review Exceptional Agents.command`, select **Arbiter of Dawn**, then Overview or Follow. Assistance arises only when an unmet need is locally observed; the normal city does not inject the test recipients. Memory & decisions and Overview show why a choice occurred. Other three profiles and the one null project slot remain reserved for 5D; no project/coordination producer is claimed yet. The current interaction uses existing idle animation, not new dialogue/gesture assets.
